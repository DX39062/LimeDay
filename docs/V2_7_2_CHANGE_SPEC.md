## 2. S1 搜索框焦点竞态修复

### 2.1 当前缺陷

用户点击搜索图标后，搜索框出现又立即关闭。原因是输入框首次进入组合时会先上报一次 `isFocused = false`，当前逻辑把这次“尚未获得焦点”误判为“已经失去焦点”，在自动聚焦执行前折叠空搜索框。

### 2.2 状态约束

- 搜索状态至少区分：折叠、请求展开、已获得过焦点、展开但未聚焦。
- 点击搜索图标先设置展开，再在节点进入组合后请求焦点和显示输入法。
- 初次出现的 `isFocused = false` 不得触发折叠。
- 只有输入框在本次展开期间确实获得过焦点，随后由 true 变为 false，且查询为空时，才允许自动折叠。
- 查询非空时失焦只隐藏输入法并保留搜索框、结果和当前滚动位置。
- 点击清除只清空查询并保留输入框焦点；点击关闭才清空查询、折叠输入框，并恢复进入搜索前的当天/逾期/计划中视图。
- 输入法“完成”只隐藏键盘，不清除查询、不折叠搜索。
- 系统返回优先由输入法关闭键盘；不得因为键盘关闭而弹出页面路由。
- 屏幕旋转和 Compose 状态恢复后保留查询、展开状态、是否已经完成首次聚焦，以及进入搜索前的智能视图。

### 2.3 验收

- [x] 空查询下首次点击搜索，搜索框稳定显示至少到用户下一次操作，不闪烁关闭。
- [x] 首次未聚焦回调不会折叠；获得焦点后再点空白处，空查询才自动折叠。
- [x] 有查询时点空白处保留结果；输入法完成只隐藏键盘。
- [x] 关闭搜索清空查询并恢复原智能视图。
- [x] 旋转后搜索状态不丢失。

## 3. S2 快速新增待办选择分组

### 3.1 布局

快速新增输入框右侧操作顺序固定为：分组按钮、添加按钮。分组按钮紧邻加号左侧。

- 分组按钮只显示当前分组的手绘图标，不显示分组名称。
- 分组按钮和加号分别拥有不少于 48dp 的独立触控目标，不允许把两个动作合成一个语义节点。
- 图形尺寸目标为 20–24dp；按钮使用当前分组的低饱和 `colorKey` 作小面积背景或描边提示。
- TalkBack 描述必须读出“选择分组，当前：<名称>”。
- 快速新增仍只在当天视图且没有搜索时显示。

### 3.2 选择浮层

- 点击分组图标打开项目自绘风格的紧凑浮层，不使用系统原生选择器。
- 列表按有效分组顺序显示图标、名称和颜色；当前项同时显示自绘勾选，不能只依赖颜色。
- 每行触控目标不少于 48dp，长名称单行省略但 TalkBack 读完整名称。
- 浮层底部固定提供“管理分组”，点击后关闭选择浮层并打开现有分组管理界面。
- “管理分组”不是常驻待办页按钮，也不是一个分组；它用于新建、重命名、换图标、换颜色、排序或删除分组。
- 没有可用普通分组时仍至少显示固定默认分组“日常”。

### 3.3 新增行为

- 快速新增接口从仅接收标题扩展为同时接收目标 `groupId`。
- 初次进入待办页时选择“日常”。
- 成功添加后保留当前分组，支持连续录入同一分组。
- 日期切换期间保留当前页面会话选择；应用进程重新启动后恢复为“日常”，不新增持久偏好。
- 当前选择被软删除、缺失或不再有效时，在显示和提交前回退到固定“日常”ID。
- 标题为空或验证失败时不得添加，也不得改变当前分组。
- 新增成功后的排序、提醒和同步元数据规则与现有快速新增一致。

### 3.4 验收

- [x] 分组图标位于加号左侧，只显示图形，两个按钮均可独立点击和朗读。
- [x] 选择分组后新增 Todo 写入正确 `groupId`。
- [x] 连续新增保留选择，重启恢复“日常”。
- [x] 分组删除或缺失后安全回退，不产生悬空新增。
- [x] 浮层底部“管理分组”能到达现有管理界面。

### 4.2 分配与编辑

- 固定默认分组“日常”使用 `daily`，不参与自动轮换。
- 新建普通分组默认选择当前有效分组尚未使用的第一个图标；全部已使用时从头循环，允许重复。
- 自动选择遵循固定顺序，不随机，不因重组或重启变化。
- 分组创建与编辑界面提供完整图标网格和现有低饱和颜色选项；用户可随时更换。
- 图标不要求永久唯一，同图标配不同颜色和名称仍是合法分组。
- 列表分组标题、快速新增选择、待办编辑器和分组管理必须使用 `iconKey` 对应图形，不再统一显示通用分组图标。

### 4.3 旧分组兼容

- 2.7.1 及更早由应用自动写入通用 `folder`、`leaf` 或空图标键的普通分组，在 2.7.2 首次规范化时按稳定的 `sortOrder + id` 顺序依次分配图标库。
- 只改已知占位键，不覆盖已具有明确图标键的分组。
- 规范化必须幂等；图标一旦不是占位键，后续启动不再修改或增加 revision。
- 分配保留分组 ID、名称、颜色、排序、Todo 引用及删除状态；只更新 `iconKey` 和正常同步元数据。
- 多设备产生差异时继续使用现有 `updatedAt/revision/deviceId` 合并规则，最终收敛；不升级 WebDAV 格式。

### 4.4 验收

- [x] 至少 16 个图标均使用 Material 主题色且以固定 Canvas 尺寸绘制，不受字体比例挤压。
- [x] 新建分组优先得到未使用图标，用户可改图标和颜色。

## 5. S4 模型服务官方 Logo 的夸张手绘重绘

### 5.1 设计原则

- OpenAI、Anthropic、Gemini、OpenRouter、DeepSeek、Kimi、通义千问、智谱 GLM、SiliconFlow、MiniMax、豆包、xAI、Mistral、Groq 与 Ollama 均按各自当前官方 Logo 的核心轮廓重新手绘。
- 实现前从厂商官方品牌页、官方产品页或官方仓库核对 Logo，不以搜索结果缩略图或第三方图包为源。
- 不直接嵌入下载的官方位图或第三方图标包；使用项目 Compose Canvas 或 VectorDrawable 重新绘制。
- 保留足以识别厂商的结构和代表色，同时加入明显的不规则轮廓、抖动线条、错位填色、重复描边和少量射线/圆点，形成“照着官方 Logo 画的夸张儿童涂鸦”。
- 不得把 Logo 简化成所有 OpenAI 兼容供应商共用的协议图标。
- 不使用复杂渐变、写实阴影、精确机械对称或与应用不协调的高饱和大色块。
- 自定义 OpenAI 兼容、未知或旧版预设使用原创手绘插头、调节线与对话框组合。

### 5.2 使用位置

同一 `presetId` 的手绘 Logo 必须一致用于：

- 新增服务预设选择。
- 模型服务卡片和编辑器。
- 当前默认服务状态。
- 每日总结和范围总结的服务选择器。
- 连接测试、模型刷新与生成来源说明中出现的供应商标识。

同厂商多个配置共用厂商 Logo，通过用户名称、模型、端点摘要和“当前默认”文字区分。所有位置同时显示厂商或配置文字，不只依赖 Logo。

### 5.3 验收

- [x] 每个内置预设映射到独立、可识别的厂商手绘 Logo。
- [x] 卡片不再仅按四类协议显示相同图形。
- [x] 未知预设安全回退，不崩溃、不修改模型配置。
- [x] 图标在 20–28dp 使用主题色和固定 Canvas 尺寸，不受字体放大影响。

## 6. S5 应用启动图标重构

### 6.1 当前问题

2.7.1 图标的巨大对勾占据主体，小尺寸下主要只能识别为“勾号”，日记本、待办列表和青柠品牌信息不足。

### 6.2 新构图

- 背景为浅薄荷或柔和蓝绿色纯色，不使用纸张纹理。
- 主体为轻微歪斜但位于安全区内的米白色手绘日记页。
- 左侧增加 2–3 个简化装订孔或短装订线，明确“日记本”语义。
- 页面内显示 2–3 行待办：第一行小对勾与短横线，第二行未完成圆圈与波浪线，第三行短波浪线。
- 对勾缩小为列表元素，不再覆盖页面大部分面积。
- 右上角保留黄绿青柠切片，并增加极少量手绘射线作为品牌强调。
- 图标内部不放“青柠日记”文字；系统启动器继续显示应用 label。
- 轮廓可有克制的不齐整和重复描边，但不能在 48px 小尺寸下糊成一团。

### 6.3 Android 资源

- 同步更新 adaptive foreground/background、普通 mipmap、roundIcon 和 Android 13 monochrome。
- 前景主体落在 adaptive icon 安全区；圆形、圆角矩形、方形和厂商特殊蒙版下不得裁掉装订、青柠或关键待办行。
- monochrome 使用日记页、列表和青柠的单色轮廓，不能退化成单独大对勾。
- 检查 48、72、96px 及启动器预览尺寸，确保首先识别为“手绘待办日记”，其次识别青柠品牌。

### 6.4 验收

- [x] 前景主体置于 adaptive icon 安全区，常见 mask 不裁掉日记页关键元素。
- [x] 小尺寸主体改为日记页与三行待办，不再是大对勾。
- [x] 普通、圆形与 monochrome 语义一致。
- [x] APK 中所有 launcher 引用均指向新版资源，无旧前景残留。

## 7. S6 全应用图标风格审计

### 7.1 必查页面与动作

- 底部导航：待办、总结、设置。
- 页面导航：返回、前进、关闭、展开、收起。
- 待办：搜索、分组、添加、完成、日期、更多、优先级、详情、移动、复制、删除、撤销。
- 分组：图标选择、颜色、排序、编辑、删除和管理入口。
- 复盘与总结：生成、发送、模型选择、日期范围、历史、收藏、展开、删除。
- 模型服务：新增、编辑、复制、测试、刷新、默认、排序、删除和所有厂商 Logo。
- 设置：外观、提醒、回收站、WebDAV、导入、导出、关于、许可。
- 回收站：选择、全选、恢复、永久删除、清空、确认。
- 月历：上月、下月、今天、日期状态和确认。

### 7.2 禁止项

- 应用源码不得导入或渲染 `androidx.compose.material.icons`、`Icons.Default`、`Icons.Filled` 或 `Icons.Outlined`。
- 不得使用 `android.R.drawable`、平台内置功能图标或系统原生选择图标。
- 不得把 Emoji、Unicode 箭头、星号或特殊字符当成功能图标。
- Material 3 可继续提供布局、语义和交互基础，但其默认 leading/trailing icon 必须由项目图形替换。
- 禁止规整的标准齿轮、机械对称加号、标准 45 度箭头等明显 Android/Material 视觉；已有近似图形必须重画为不规则涂鸦版本。

### 7.3 统一规则

- 应用动作图标统一使用深墨绿不规则线条、圆润端点、轻微错位与少量薄荷/柠黄填色。
- 同一动作跨页面使用同一图形；不同动作不得复用易混淆图形。
- Canvas/VectorDrawable 必须显式设置视觉尺寸；常见图形 20–26dp，触控目标不少于 48dp。
- 选中、未选中、禁用和危险状态必须同时通过图形/文字/边框表达，不仅依赖颜色。
- 所有可点击图标具有 TalkBack 描述；纯装饰图形从语义树排除。
- 系统状态栏、通知栏、输入法、系统权限弹窗、系统文件选择器和系统分享面板不属于应用可重绘范围。
